# Local folders in the browser

What a web page can read of a folder on the person's machine, and what a git index holds, as measured for
[local repositories](../specs/007-local-repositories/local-repositories.md).
Measured with Playwright 1.64's builds: Chromium 156, Firefox 157 and WebKit 27.2 (Safari's engine), on Linux.

## Folder access per browser

| Engine   | Directory handle (`showDirectoryPicker`) | Folder input (`webkitdirectory`)                   | Hidden entries (`.git`, `.gitignore`) |
| -------- | ---------------------------------------- | -------------------------------------------------- | ------------------------------------- |
| Chromium | yes, in a secure context                 | yes; lists every file before the page hears of it  | listed                                |
| Firefox  | no                                       | yes; lists every file before the page hears of it  | listed                                |
| WebKit   | no                                       | yes, but leaves out every name starting with a dot | left out: no `.git`, no `.gitignore`  |

- Measured, not inferred: a fixture holding `.git/`, `.github/`, `.gitignore`, `node_modules/` and two symbolic links
  was set on a folder input in each engine (Playwright hands the folder to the engine, which lists it natively).
  Chromium and Firefox listed every entry, the dot ones included; WebKit listed only `package.json`, `src/a.ts` and
  `node_modules/x/i.js`.
- So Safari cannot see a repository's index or its ignore files: a page there would lay `node_modules` and build output
  as if they were source, without knowing it. `navigator.vendor` is `Apple Computer, Inc.` in WebKit only (Chromium:
  `Google Inc.`, Firefox: empty).
- Symbolic links are skipped by both Chromium's and Firefox's folder listing (neither the file link nor the loop to
  `..` appeared). Git tracks a link as a file (mode `120000`), and the index lists it, so the git path keeps it.
- The listing comes whole, after the browser has walked the folder; no event arrives before. The linux working tree
  (102,408 entries, 96,106 files, a 10 MB index) listed in 3.6 s in Chromium and 3.4 s in Firefox; finding and reading
  the index among the files then took 47 to 60 ms. A folder with a large `node_modules` lists for proportionally longer,
  and its size is unknown to the page until the listing arrives.
- A directory handle reads only what it is asked for: the index, a few small files of `.git/` and the root manifests.
  Origin private file system handles (`navigator.storage.getDirectory()`) are real `FileSystemDirectoryHandle`s, answer
  `queryPermission` with `granted`, and store in IndexedDB in Chromium, so the handle path can be driven end to end
  without the native dialog. Firefox's are storable too; WebKit's failed in this build.
- A handle stored in IndexedDB survives a reload (measured); Chromium asks again (`requestPermission`, which needs a
  user gesture) unless the person granted "Allow on every visit" (inferred from Chromium's persistent permissions).

## The git index in the wild

- Every checkout in the reference corpus (`~/.cache/citymap/repos`, 20 with an index, from 183 to 67,291 entries) holds
  a version 2 index with only the cache-tree extension (`TREE`) and no extended flags. Three (linux, godot, vscode) are
  clones without a checkout and hold no index at all.
- What git itself writes, generated by `apps/web/scripts/index-fixtures.ts` with git 2.43:

| Case                                          | Version | Extensions                     |
| --------------------------------------------- | ------- | ------------------------------ |
| a plain checkout, links, submodules           | 2       | `TREE`                         |
| intent-to-add or skip-worktree entries        | 3       | `TREE`                         |
| `index.version = 4` (also `feature.manyFiles`) | 4       | `TREE`                         |
| a resolved conflict                           | 2       | `TREE`, `REUC`                 |
| untracked cache, fsmonitor, index threads     | 2       | `IEOT`, `TREE`, `UNTR`, `FSMN`, `EOIE` |
| `index.skipHash` (also `feature.manyFiles`)   | 2       | `TREE`; the checksum is zeros  |
| SHA-256 objects                               | 2       | `TREE`; 32-byte object ids     |
| split index                                   | 2       | `link`, `TREE`                 |
| sparse index                                  | 3       | `TREE`, `sdir`                 |

- An extension whose signature starts with an upper-case letter is optional: a reader that does not know it may skip it.
  `link` and `sdir` are lower case: a reader that does not understand them must not use the index, and indeed without
  the shared index (`link`) or with folders standing for their files (`sdir`) the entries are not the tracked files.
- An entry's flags hold its path length up to 4,094; a path of 4,095 bytes or more says 4,095, so the reader finds the
  path's end by its terminating zero byte.
- The object id width (20 or 32 bytes) is not in the index: it is `extensions.objectformat` in `.git/config`.

## Matching `.gitignore`

| Option                   | Licence | Size              | Correctness                                                             |
| ------------------------ | ------- | ----------------- | ----------------------------------------------------------------------- |
| `ignore` 7.0.12          | MIT     | 47 KB, no deps    | tested against `git check-ignore`; recent releases close the last gaps  |
| own matcher              | ours    | about 150 lines   | every rule of gitignore(5) to reimplement and test: escapes, `**`, `!`  |

- `ignore` is the matcher behind ESLint and Prettier; 7.0.8 to 7.0.12 (2026) brought escapes, trailing spaces, a lone
  `!` and `dir/` checks in line with git. It matches paths relative to one `.gitignore`; nesting is the caller's: each
  folder's rules apply to the paths beneath it, deeper files override, and a folder excluded is never entered.
